# Multi-Modal GraphRAG for Scientific Literature QA

This repository implements a large-scale, multi-modal Retrieval-Augmented Generation (RAG) pipeline optimized for scientific literature. It is designed as the foundational knowledge engine for an autonomous research agent, capable of executing complex, multi-step reasoning across dense academic texts, figures, and equations.

## System Architecture

The pipeline processes raw PDFs into a queryable semantic knowledge graph and multi-vector store.

- **Document Ingestion:** Utilizes MinerU for layout-aware PDF parsing, extracting distinct structural blocks (text, titles, figures, equations) into standard JSON and Markdown formats.
- **Hybrid Chunking & Prefixing:** Employs a custom chunker that splits text based on a combination of token limits and layout boundaries (e.g., headings). Each chunk is enriched with a contextual prefix generated by an LLM to situate it within the broader document context.
- **Knowledge Graph Construction:** Processes chunks using a local LLM (Qwen3-32B-AWQ via vLLM) to extract atomic entities and directed relationships. These are compiled into a NetworkX graph (`.graphml`) for structural reasoning.
- **Dual-Encoder Retrieval:**
  - **Semantic:** Uses `BAAI/bge-m3` and Qdrant to store and query dense vectors of chunk texts, contextual summaries, and entity descriptions.
  - **Visual (Multi-Vector):** Implements ColPali (ColQwen2) for late-interaction matching between user queries and rendered document pages or visual blocks.
- **Generation:** Routes contexts to a local Vision-Language Model (Gemma-4-26B-AWQ) for final answer synthesis.

## Prerequisites

- **OS:** Linux (tested on Ubuntu)
- **Hardware:** NVIDIA GPU with sufficient VRAM (minimum 24GB recommended for AWQ/INT4 quantised local LLMs, e.g., RTX 3090 
- **Dependencies:** Docker, Docker Compose, Python 3.10+

## Installation

1. Clone the repository and initialise the environment:

```bash
git clone <repository_url>
cd rag
uv venv
source .venv/bin/activate
uv pip install -r requirements.txt
```

2. Configure environment variables in `.env`:

```env
APP_HF_TOKEN="your_huggingface_token_here"
```

3. Verify paths in `src/config.py` align with your local storage mounts (e.g., `/storage/bulk/raw_docs`).

## Usage

### 1. Start Infrastructure Services

Spin up Qdrant and the vLLM server via Docker Compose:

```bash
./start.sh
```

### 2. Run the Offline Data Pipeline

The pipeline orchestrates document parsing, chunking, entity extraction, and vector embedding:

```bash
./scripts/offline_graph.sh
```

> **Note:** Uncomment specific Python modules in `offline_graph.sh` to run isolated stages (e.g., `src.ingest.parse_docs`, `src.graph.build_graph`).

### 3. Inference & UI

Once the database and graph are populated, launch the Streamlit dashboard:

```bash
streamlit run src/inference/ui/app.py
```

Alternatively, use the inference module programmatically:

```python
from src.inference.inference import InferencePipeline

pipeline = InferencePipeline()
result = pipeline.run("Explain the mechanism of FlashAttention.")
print(result["answer"])
```

## Evaluation

The evaluation suite uses `ragas` to assess `faithfulness`, `answer_relevancy`, and `context_precision`.

1. Generate the synthetic test dataset from ingested Markdown documents:

```bash
./scripts/generate_dataset.sh
```

2. Execute the evaluation harness (also runs automatically on CI/CD via `.github/workflows/eval.yaml`):

```bash
python -m evals.run_eval --threshold 0.75
```
